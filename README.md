# 收果预约与机动线值班分析

趟次事件和设备资料均为合成记录。所有时区偏移已在来源格式中说明。

`data` 保存原始记录，`DATA.md` 是资料字典。`citrus` 是只读的分析程序：读取 `data/`，把值班报告写到 `reports/`，把调度员确认的处置写到 `state/`，不会改写原始记录。

## 快速开始

环境使用 Python 3.11.2。

```sh
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
```

常用命令：

```sh
# 生成某个观测时点的值班报告（写入 reports/duty_report.md）
python3 -m citrus.cli --as-of 2026-11-09T06:40:00+08:00 report --out reports/duty_0640.md

# 只看两种等待口径与承诺
python3 -m citrus.cli --as-of 2026-11-09T06:40:00+08:00 summary

# 按趟次或门查找当前预警及当时可见依据
python3 -m citrus.cli --as-of 2026-11-09T06:40:00+08:00 warnings --trip V14-05
python3 -m citrus.cli --as-of 2026-11-09T06:40:00+08:00 warnings --gate 西门

# 比较机动线处置选项（可加 --json）
python3 -m citrus.cli --as-of 2026-11-09T06:40:00+08:00 options

# 查看候车带断记区间内哪些趟次仍可确认
python3 -m citrus.cli quality
```

省略 `--as-of` 时使用 `policy.json` 的第一个观测时点。程序只读取本地数据，不访问业务系统。

## 口径要点

- **趟次不是车牌**：`trip` 才是趟次标识，同一车牌会跑多趟；同趟重复的候车登记只算一次。
- **两种等待口径分开报**：
  - 用户等待 = 首次有效到达 → 卸完或放弃；放弃者的等待按实际离开时刻计入。
  - 预约完成承诺 = 是否在 `promised_complete_by` 前卸完；放弃一律算未达成。
  - 只看进过门或只看卸完的车，会把掉头的司机移出样本，平均等待反而变好看，报告里保留这个对照。
- **不确定不当作零**：仍在排队或场内的趟次是右删失（只知下界），分位数与超时比例给上下界；上界不可识别时明确写“不可识别”。
- **断记不悄悄踢样本**：候车带已知断记区间内、但能由其他来源确认的趟次按到达区间保留；无法确认的单列“到达不明”。
- **回放不倒账**：预警只引用当时 `arrived_at` 已可见的记录；后来的离场记录不能用来撤销当时的预警理由。
- **口径不重复计数**：改门的整趟等待只记在最终使用的门上，门位占用按 `[开始, 结束)` 区间保留。
- **处置受约束**：只能用预约允许的门；已叫号或已进场的车不改排；机动线转门有 20 分钟停机、一个时段只服务一处；已确认的调令是后续推演的起点。

## 输出约定

- `reports/`：Markdown 值班报告，可随时重新生成，不需要入库。
- `state/decisions.json`：调度员确认的处置。后续比较会把它当作已确认调令继承；未开始的建议可以被新建议替换，正在转运或已占用的资源不会在两个门重复计算。

确认一项处置：

```sh
python3 -m citrus.cli --as-of 2026-11-09T06:45:00+08:00 confirm \
  --action move --from-gate 北门 --to-gate 西门 \
  --start-at 2026-11-09T07:00:00+08:00 --ready-at 2026-11-09T07:20:00+08:00 \
  --operator 值班员 --note "06:40 视图确认" --supersede M1
```
